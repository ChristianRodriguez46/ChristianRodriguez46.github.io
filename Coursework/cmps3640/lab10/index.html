CMPS 3640 · Lab 10

C++ threads

Three short exercises with C++ std::thread: starting and joining two threads, splitting an array addition between two threads and timing it against a single loop, and summing an array with four threads that combine their partial sums under a mutex. In the run below the two-thread addition comes out slower than the single loop, because it runs first and pays for the first writes to the 400 MB result array.

View code on GitHubREADME

What I did

  • Wrote Lab10_Activity1.cpp, which starts one thread printing 1 to 10 and another printing A to N, and joins both before exiting.
  • Wrote Lab10_Activity2.cpp, which adds two 100-million-element arrays with one thread per half, then repeats the addition in one loop and prints both times and the speedup.
  • Wrote Lab10_Activity3.cpp, which creates four threads in a loop, has each sum its section into a local variable, adds that to a shared total under a std::mutex, and checks the result against the expected sum.

How to build and run

From the folder with the code:

g++ -pthread -o act1 Lab10_Activity1.cpp && ./act1
g++ -pthread -o act3 Lab10_Activity3.cpp && ./act3

Requires: g++ with OpenMP (-fopenmp) and POSIX threads (-pthread), standard on Linux.
