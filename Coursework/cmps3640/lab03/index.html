CMPS 3640 · Lab 3

Computing pi in parallel

Approximates pi by integrating 4/(1+x²) from 0 to 1 with the midpoint rule, first sequentially and then in two OpenMP versions that split the steps among threads in different ways. Each version prints its error against pi and the time taken.

View code on GitHubREADME

What I did

  • Started from the sequential pi.cpp (its header credits Tim Mattson), which uses 1,000 steps and compares against 3.14159.
  • Wrote pi_4A.cpp, where thread id takes steps id, id + NT, id + 2·NT and so on, and pi_4B.cpp, where each thread takes one block from id * N / NT to (id + 1) * N / NT and the last thread also takes any remainder.
  • Kept one partial sum per thread in a shared cumsum array, recorded the real team size from thread 0, and added the partial sums after the parallel region.
  • Used 1,000,000 steps and compared against atan(1) * 4 in both parallel versions.

How to build and run

From the folder with the code:

g++ -fopenmp -O2 -o pi pi.cpp && ./pi
g++ -fopenmp -O2 -o 4a pi_4A.cpp && ./4a
g++ -fopenmp -O2 -o 4b pi_4B.cpp && ./4b

Requires: g++ with OpenMP (-fopenmp) and POSIX threads (-pthread), standard on Linux.
