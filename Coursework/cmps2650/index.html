Linux Environment and Administration

The commands I used for each CMPS 2650 lab, and what they do.

Labs 1 to 10 cover the command line, editors and shell scripting. The admin labs cover running a Debian system: users, passwords, storage, services and DNS. The lab handouts are the instructor’s and are not included, so each lab starts with the task in my own words. Server addresses, other users’ information and password hashes are left out.

All coursework

  • Lab 1

    Exploring the Linux system

    A first look around the server: the running kernel, the standard directories, and how Linux represents hardware as files.

    • Kernel information
    • Filesystem hierarchy
    • Device files

    Which kernel is running?

    cat /proc/version     # kernel version, compiler and build date
uname -a              # the same information in one line

    What is /usr for?

    /usr holds installed software that is shared by every user: programs in /usr/bin, libraries in /usr/lib, and documentation in /usr/share. (System configuration lives in /etc, not /usr.)

    How does Linux show devices?

    Hardware is represented as special files in /dev, for example disks (/dev/sda) and terminals (/dev/pts/N). Programs read and write these files to talk to the device.

    What is /dev/null?

    A device that discards everything written to it. It is used to hide unwanted output, for example command 2>/dev/null drops error messages, and > logfile (or cat /dev/null > logfile) empties a log file.

  • Lab 2

    Hosts, terminals and remote access

    Identifying the machine and session you are logged in to, basic network tools, and copying files over SSH.

    • hostname and /etc/hosts
    • Terminals
    • SSH and X11 forwarding
    • scp

    Which machine am I on?

    hostname            # the machine's name
hostname -I         # its IP address(es)
cat /etc/hosts      # local name-to-address table

    /etc/hosts maps names to addresses before DNS is consulted. On Debian, the machine's own hostname is mapped to 127.0.1.1, a loopback address, so the system can always resolve its own name.

    Which terminal am I using?

    tty            # e.g. /dev/pts/33: the pseudo-terminal for this SSH session
who am i       # my login with its terminal

    Network tools

    • netstat shows network connections, routing tables, interface statistics and multicast memberships (ss is the modern replacement).
    • In ping output, TTL (time to live) is the number of routers a packet may still pass through before it is discarded, which stops packets from looping forever.

    Graphical programs over SSH

    ssh -X user@server   # untrusted X11 forwarding: remote programs get limited access to your display
ssh -Y user@server   # trusted forwarding: fewer restrictions, less secure

    Use -X by default and switch to -Y only when a program does not work under -X.

    Copying files

    scp notes.txt user@server:~/      # upload
scp user@server:~/notes.txt .     # download

  • Lab 3

    Disk usage, links, find and text pipelines

    Measuring disk usage, creating symbolic and hard links, searching with find, and building pipelines with sort, uniq, tr and wc.

    • du
    • Symbolic and hard links
    • find with -exec
    • sort, uniq, tr, wc

    Disk usage

    du -sh       # total size of the current directory, human-readable
du -h ~      # every folder under home; the last line is the account total

    Directories and links

    mkdir -p ./US/California/Kern/Bakersfield   # -p also creates the missing parent folders
mkdir -p ./US/California/Kern/Shafter
ln -s US/California/Kern/Bakersfield bako   # symbolic link to a deep directory
ls -al                                      # bako's permissions start with "l" (a link)
cd bako && echo "Bakersfield - Home of CSUB" > test.txt && cat test.txt
pwd                                         # shows the path through the link: .../bako

    echo prints the text and > redirects it into test.txt, creating or overwriting the file.

    ln -s US/California/Kern/Bakersfield/test.txt sltest.txt   # symbolic link
ln    US/California/Kern/Bakersfield/test.txt hltest.txt   # hard link (no -s)
    • The hard link's permissions start with -: it is another name for the same file, so it shows the file's real size and modification time.
    • The symbolic link is a small file containing a path, so its size is the length of that path and its time is when the link was created.
    • Deleting either link leaves the original test.txt in place.

    find

    find /etc -type f -name "a*"              # files under /etc whose names start with "a"
find ~ -type f -empty                     # empty files in my account
find . -not -name "*.cpp"                 # everything (files and directories) except .cpp files
find ~ -name "*.cpp" -perm -004           # .cpp files readable by everyone ("the world")
find ~ -name "*.cpp" -perm -004 -exec chmod o-r '{}' \;   # remove world-read from each one
find ~ -type f -mtime -365                # files modified in the last year
find ~ -type f -mtime -365 | wc -l        # ...and how many there are

    After the chmod, running the -perm -004 search again returns nothing, because no .cpp file is world-readable any more.

    Pipelines

    who | sort > who.txt                          # logged-in users, sorted, saved to a file
uniq who.txt                                  # collapse repeated adjacent lines
awk '{print $1}' who.txt | sort | uniq | wc -l   # count unique users
uniq who.txt > who2.txt
cat who2.txt | tr -s ' ' > who3.txt           # squeeze repeated spaces into one
cat who3.txt | tr -d ' ' > who4.txt           # delete all spaces
cat who4.txt | tr '\n' ',' > who5.txt         # turn newlines into commas: one comma-separated line
diff who4.txt who5.txt                        # shows the line-per-name vs. single-line difference

    The who output files themselves are not included because they list other users of the server.

  • Lab 4

    Basic regular expressions with grep

    Matching text with basic regular expressions (BREs) in grep. text.txt is the sample file the commands run against.

    • Anchors and character classes
    • Repetition \{n,m\}
    • grep -o, -i, -c, -v
    grep "apple" text.txt              # exact case
grep -i "apple" text.txt           # any case
grep "^Apple" text.txt             # "Apple" at the start of a line
grep '[A-Z]\{2,\}' text.txt        # two or more capital letters in a row (BRE)
grep -E '[A-Z]{2,}' text.txt       # the same with extended regex, no escaping needed
grep ', M[A-Z]$' text.txt          # cities in states whose code starts with M

    Matching patterns

    echo "X9YZ XX1YZ"         | grep -o "X[369]YZ"            # X, one of 3/6/9, then YZ
echo "X333YZ X369YZ X123YZ" | grep -o "X[369]\{3\}YZ"      # three digits, each 3, 6 or 9
echo "what? X6?9 no"       | grep -o '[^ ]*[?][^ ]*'       # words containing a question mark

    Practical patterns

    grep -o "[0-9]\{3\}-[0-9]\{2\}-[0-9]\{4\}"     # US Social Security number format
grep "//" program.cpp                            # lines with // comments
grep -c "^[[:space:]]*$" file.txt                # count blank lines
grep -v "^[[:space:]]*$" file.txt > clean.txt    # copy the file without blank lines

  • Lab 5

    Regular expressions in grep and vi

    Search-and-replace with regular expressions inside vi, and extended regular expressions (EREs) in grep. The lab used song lyrics as sample text; that file is not included.

    • vi substitution
    • :g and :v
    • Extended regular expressions
    • Backreferences

    grep

    grep -o "Bel-Air" lyrics.txt | wc -l      # how many times a phrase appears (not just matching lines)

    vi substitutions

    Command What it does
    :%s/?$/??/g Double every question mark at the end of a line
    :1,$v/?$/s/$/,/ Add a comma to every line that does not end with ?
    :1,$-1v/?$/s/$/,/ The same, but skip the last line
    :1,$v/?$/s/$/,/gc The c flag asks before each replacement
    :g/^[ ]*$/d Delete blank lines (lines of only spaces)
    :1,15s/^/\/\/ / Comment out the first 15 lines of a C++ file by adding //

    :g/pattern/command runs a command on every line that matches; :v/pattern/command runs it on every line that does not.

    Extended regular expressions

    grep  "(\bI\b|\bme\b|\bmy\b)" lyrics.txt     # matches nothing: ( ) and | are ERE syntax
grep -E "(\bI\b|\bme\b|\bmy\b)" lyrics.txt   # lines containing the words I, me or my
egrep "(\bI\b|\bme\b|\bmy\b)" lyrics.txt     # same as grep -E

echo "Arrow, Arrowhead, Wheelbarrow, Bone marrow, Tomorrow" |
  grep -Eo "\bArrow(head)?\b|\bWheelbarrow\b|\bBone marrow\b"   # everything except Tomorrow
grep -Eo "[0-9]{3}-[0-9]{2}-[0-9]{4}"                               # SSN format

    Strings that match each pattern

    Pattern Two matching examples
    [0-3]*\d+\l? 00312a, 2319x
    (ha){2,}.* haha, hahahaha!
    [ba][ba](na){2} banana, abnana
    X\([abc]\)Z\([0-9]+\)\2 XaZ55, XcZ123123

    vim skills and shell profiles

    Moving around and reformatting code in vim, then customizing the shell through .bash_logout, aliases and the prompt. hello.cpp is the file used for the indenting and folding steps.

    • vim marks, search and indentation
    • Code folding
    • .bashrc, .bash_logout, aliases, PS1

    vim

    Keys What they do
    mw, then `w Set mark w, then jump back to the exact character where it was set
    'w Jump to the start of the line holding mark w
    gg Go to the top of the file
    /prince, then / + Up + Enter Search forward and repeat the search
    :r!ls $HOME Insert the output of a shell command into the file
    =iB Re-indent everything inside the surrounding { } block
    4== Re-indent the current line and the next three
    >% / <% Indent or outdent through the matching bracket
    >> / << Indent or outdent the current line
    zf%, zc, zo Create a fold through the matching bracket, close it, open it

    Code folding collapses a block of code into one line so you can see the structure of a file without the details, the same as in an IDE.

    Profiles

    # appended to ~/.bash_logout: record when and where each session ended
echo "`date` from `pwd`" >> ~/logout_history.txt

alias                            # list current aliases
alias name="command"             # define one (put it in ~/.bashrc to keep it)

echo 'rm -f ~/.bash_history' >> ~/.bash_logout    # clear command history at every logout

# a colored prompt: user@host:directory time, then $ on a new line
PS1='\[\e[1;36m\]\u@\h:\[\e[0m\]\[\e[1;34m\]\w\[\e[0m\] \@\n\$ '

  • Lab 7

    Bash scripting, part 1

    How a script's interpreter is chosen, exit codes, and a script that reports whether a C++ file compiles.

    • Shebang lines
    • Exit status $?
    • Redirecting stderr

    Running a script different ways (lab7-01.sh)

    sh lab7-01.sh        # fails: sh is a basic POSIX shell without bash's += operator
bash lab7-01.sh      # works: prints "Hello, Scripts"
chmod u+x lab7-01.sh
./lab7-01.sh         # works: the #!/bin/bash line makes the kernel run it with bash

    Writing H = "Hello" with spaces breaks the script: bash reads H as a command name and reports H: command not found. Assignments in bash must not have spaces around =.

    Exit codes (argcount.cpp)

    g++ argcount.cpp
./a.out alpha bravo charlie delta
echo $?        # 4: the program returns argc - 1, so $? is the number of arguments

    $? always holds the exit status of the last command; 0 conventionally means success.

    Does it compile? (lab7-02.sh)

    ./lab7-02.sh hello.cpp     # prints "Compile successful" or "Compile failed"

    The script runs g++ "$1", sends compiler errors to /dev/null with 2>/dev/null, and checks $?. hello.cpp in this folder is broken on purpose, to test the "Compile failed" branch.

  • Lab 9

    diff and patch

    Creating a patch file from two versions of a program, applying it, and rolling it back. hello.patch is the patch I produced.

    • diff -u
    • patch and patch -R
    • sed -i
    cat > hello.c << EOF            # create the original program with a here-document
...
EOF
gcc hello.c -o hello && ./hello                 # Hello, World!

cp hello.c hello_new.c
sed -i 's/Hello, World/Hello, Unix World/' hello_new.c

diff -u hello.c hello_new.c > hello.patch       # unified diff: the patch file
cp hello.c hello_original.c
patch hello_original.c < hello.patch            # apply it
gcc hello_original.c -o hello_patched && ./hello_patched   # Hello, Unix World!

patch -R hello_original.c < hello.patch         # roll it back
gcc hello_original.c -o orig && ./orig          # Hello, World! again

    In the unified diff, lines starting with - are removed and lines starting with + are added; the @@ -1,6 +1,6 @@ header gives the line ranges in each file.

  • Lab 10

    sed, awk, nano and emacs

    The same text edits done with sed and awk on students.txt, then configuring nano and emacs. emacs-f5-compile-run.el is my emacs setting that saves, compiles and runs the current file with F5.

    • sed substitution
    • awk fields and totals
    • Editor configuration

    sed and awk

    sed 's/Bob/Robert/' students.txt        # prints the change; the file is untouched
sed -i 's/Bob/Robert/' students.txt     # -i edits the file in place
awk '{gsub("Bob","Robert"); print}' students.txt

sed 's/.*[[:space:]]//' students.txt    # scores only (drop everything up to the last space)
awk '{print $2}' students.txt           # scores only (second field)

awk '{total += $2; count++} END {print total/count}' students.txt   # average score

    sed works on text patterns, while awk splits each line into fields and understands numbers, which makes it the better tool for comparisons and totals.

    emacs

    • C- means Ctrl and M- means Alt (Meta).
    • C-x 2 splits the window top and bottom, C-x 3 splits it side by side, and C-x 0 closes the current window.
    • emacs-f5-compile-run.el adds an F5 command to ~/.emacs: it saves the file, then compiles and runs it with the right command for C, C++, Java, Python or Go.

  • Admin lab 1

    Users and groups

    Creating and managing user accounts and groups on a Debian virtual machine.

    • useradd, usermod, groupadd, gpasswd
    • /etc/passwd and /etc/group
    sudo useradd -m adam                      # new user with a home directory
sudo groupadd warriors                    # new group (next free GID)
sudo groupadd -g 9999 fighters            # new group with a chosen GID
id adam                                   # UID, primary group and supplementary groups

sudo usermod -aG warriors adam            # add adam to a supplementary group (-a keeps existing ones)
sudo usermod -aG fighters,warriors adam   # several groups at once
sudo useradd -m -g warriors benjamin      # new user whose primary group is warriors
sudo gpasswd -d adam warriors             # remove adam from warriors
    • A new user's UID usually matches the GID of their personal group (for example 1001:1001), while a group created with -g uses the number you give.
    • The account created at install time belongs to many extra groups (such as audio, video, plugdev, netdev), which give it access to devices; a new user only belongs to its own group.
    • grep -E '^[^:]*:[^:]*:([0-9]+):\1:' /etc/passwd lists accounts whose UID equals their primary GID; adding -v lists the ones that differ.
    • Typing arrow keys where a program is not expecting them prints escape sequences, which show up as ^[[A, ^[[B, ^[[C and ^[[D (up, down, right, left).

  • Admin lab 2

    Passwords and login policy

    How Linux stores password hashes, password-strength rules with PAM, and default files for new users.

    • /etc/shadow hash format
    • PAM password rules
    • /etc/skel

    /etc/shadow

    Each entry stores the hashed password as $id$parameters$salt$hash:

    • $y$ means the yescrypt algorithm (Debian's default).
    • The parameters block sets yescrypt's cost.
    • The salt is random per user, so two people with the same password get different hashes.
    • The rest is the derived hash. The actual value from the lab is not shown here.

    Password strength with PAM

    password requisite pam_cracklib.so retry=3 minlen=8 difok=3

    Check new passwords for strength, allow 3 tries, require at least 8 characters, and require at least 3 characters to differ from the old password.

    Defaults for new users

    Files in /etc/skel are copied into every new user's home directory. Adding a line such as # TEST LINE to /etc/skel/.profile means every account created afterward starts with that line.

    Storage

    Finding disks, partitions and filesystems, measuring disk usage, and viewing directory trees.

    • lsblk, df, du, parted
    • Filesystem types
    • tree

    sudo apt update && sudo apt install -y tree
tree -P "*.conf" /etc         # only files matching a glob
sudo tree / -L 3 --du -h      # three levels deep with sizes
sudo tree / -L 3 --du -h -d   # directories only

  • Admin lab 4

    Logical volume management (LVM)

    Working with LVM volume groups and logical volumes on the virtual machine, then mounting them.

    • LVM volume groups and logical volumes
    • Mounting filesystems
    sudo mount /dev/vg01/vol_data /mnt/data    # mount the logical volume vol_data from volume group vg01

    LVM device paths follow /dev/<volume group>/<logical volume>. Because logical volumes are not tied to one physical partition, they can be resized or moved across disks later.

  • Admin lab 5

    Services and scheduled jobs

    Managing services with systemd and scheduling commands with cron.

    • systemctl
    • ss for listening ports
    • crontab syntax

    systemd services

    systemctl list-units --type=service --state=running   # services running now
systemctl list-units --type=service --state=active    # all active services
sudo ss -tulpn | grep sshd                             # which port SSH listens on (22)

sudo systemctl status apache2     # is the web server running?
sudo systemctl start apache2      # start it now
sudo systemctl enable apache2     # start it at every boot
sudo systemctl restart apache2    # restart after a configuration change

    cron

    # every 5 minutes, append the date to a log
*/5 * * * * date >> ~/date.log

# at midnight on December 25, add a message to the login banner
0 0 25 12 * echo "Merry Christmas" >> /etc/motd

    The five fields are minute, hour, day of month, month and day of week. To test the December job without waiting, set the clock just before it with sudo date -s "2025-12-24 23:59:00".

    The sample script reviewed in this lab notifies users about their disk usage when quotas are in place, so it is the kind of job cron would run on a schedule.

  • Admin lab 7

    DNS lookups

    Querying DNS records and domain registration details.

    • dig record types
    • SOA and MX records
    • whois
    dig example.com                  # A records; repeat queries can return different addresses
sudo resolvectl flush-caches     # clear the local DNS cache (older systems: systemd-resolve --flush-caches)
dig soa example.com              # start of authority: primary name server, admin, serial and timers
dig mx example.com               # mail servers with priorities
whois example.com                # registrar, expiration date and name servers
    • In an SOA record, the numbers after the two names are the serial number, refresh, retry, expire and minimum TTL, in seconds.
    • In MX records, the lower priority number is tried first; servers with the same number share the load.
    • .edu domains have a single registrar, EDUCAUSE, which manages the whole .edu zone.
