CMPS 3600 · Lab 10

Dot product with threads and pipes

A dot product split across eight threads and two processes. Each thread computes a partial sum and writes it into a pipe, and a forked child reads the pipe until it is empty and adds the parts. The other files explore pipes, page faults, the cache and resource limits.

View code on GitHubREADME

What I did

  • Started from the instructor's threaded dotprod.c.
  • Created the pipe before fork, kept the write end in the parent and the read end in the child.
  • Had each thread write its partial sum to the pipe inside the mutex, and print it when the program is run with 1.
  • Closed the write end after joining the threads, so the child's read loop ends, then printed the child's exit code from waitpid.
  • Wrote mypipes.c, a first look at the two descriptors pipe returns.

How to build and run

From the folder with the code:

make
./bblab10

Requires: Linux with gcc and POSIX threads. The graphical labs also need the X11 development headers (sudo apt install libx11-dev libxext-dev on Ubuntu). Every folder has a Makefile.
