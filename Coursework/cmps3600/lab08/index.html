CMPS 3600 · Lab 8

Threads, fork and exec

Five threads pass a semaphore "baton" in a fixed order even though they are created in reverse. Afterward the program removes its semaphore by running ipcrm with execve, either in place of itself (0) or from a forked child (1).

View code on GitHubREADME

What I did

  • Started from the instructor's xlab8.c, which sets up the baton threads and leaves the cleanup to the student.
  • Added a usage message with examples for each option.
  • Built the ipcrm -s <semid> argument list and ran it with execve.
  • With 1, forked a child to run ipcrm and had the parent wait for it and print its exit status; with 0, called execve directly, so the program is replaced and nothing after it runs.

How to build and run

From the folder with the code:

make
./lab8 1

Requires: Linux with gcc and POSIX threads. The graphical labs also need the X11 development headers (sudo apt install libx11-dev libxext-dev on Ubuntu). Every folder has a Makefile.
