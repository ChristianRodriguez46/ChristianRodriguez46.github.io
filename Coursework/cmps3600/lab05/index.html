CMPS 3600 · Lab 5

Ordering processes with semaphores

Fixing a race condition with a semaphore. In the starter code the child reads shared memory before the parent has written fib(n) to it, so it prints 0. bblab5.c adds a System V semaphore that makes the child wait until the value is ready.

View code on GitHubREADME

What I did

  • Started from the instructor's lab.c, which shows the race.
  • Created a one-semaphore set with semget and set it to 0 with semctl(SETVAL).
  • Defined a two-step grab (wait for zero, then add 1) and a release (subtract 1), the pattern used in class.
  • Had the parent grab the semaphore before fork and release it only after writing fib(n), so the child blocks on its own grab until the value is there.
  • Wrote practice/mysemaphore.c, which alternates a parent and child with two named POSIX semaphores.

How to build and run

From the folder with the code:

make
./bblab5

Requires: Linux with gcc and POSIX threads. The graphical labs also need the X11 development headers (sudo apt install libx11-dev libxext-dev on Ubuntu). Every folder has a Makefile.
