CMPS 3600 · Lab 4

Shared memory and message queues

A parent and child that talk through two System V IPC channels. The parent writes a number into shared memory, which the child polls for, then sends a word through a message queue. The child writes both to log. A second program, myxwindow.c, forks a child X11 window and notices when it closes.

View code on GitHubREADME

What I did

  • Built one IPC key with ftok from the foo file and used it for both shmget and msgget.
  • Had the child poll the shared integer with usleep until the parent changes it, then block on msgrcv for the word.
  • Removed the queue in the child and the shared memory in the parent with msgctl and shmctl, so nothing is left behind.
  • Extended the instructor's X11 window in myxwindow.c: C forks a child window, A switches the colors, and a SIGCHLD handler shows "Child has died" in the parent window.
  • Wrote practice/myshared.c, a first shared memory test.

How to build and run

From the folder with the code:

make
./lab4
cat log
./cleanipc.sh $USER  # if a run is interrupted

Requires: Linux with gcc and POSIX threads. The graphical labs also need the X11 development headers (sudo apt install libx11-dev libxext-dev on Ubuntu). Every folder has a Makefile.

This program opens an X11 window

It needs an X server on the computer you are looking at. On Linux that is already part of the desktop. On a Mac or a Windows PC, or when the program runs on another machine over SSH, see Setting up X11 for what to install and how to check it works.
