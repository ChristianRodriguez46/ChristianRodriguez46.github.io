Setting up X11 for the graphics labs

Most of the graphical programs in CMPS 3600, and the OpenGL games in CMPS 3350, draw their windows with X11. To see those windows you need an X server on the computer in front of you. This page lists what to install on a Mac, a Windows PC or Linux, and two quick tests that show it works.

Two ways to run them

  • On a Linux computer with a desktop. X11 (or Xwayland) is already running. Install the development packages below, then build and run the lab in a terminal.
  • On a Linux server, with the windows sent to your computer. The program runs on the server and its windows open on your screen through SSH X11 forwarding. Your computer needs an X server for this: XQuartz on a Mac, or one of the Windows options below.

Mac

  1. Install XQuartz, the X server for macOS.
  2. Open Terminal and connect with X11 forwarding turned on: 
    ssh -Y username@your-linux-server
  3. For OpenGL programs (glxgears and the CMPS 3350 games), XQuartz must allow indirect OpenGL. Quit XQuartz, run this once, then open it again: 
    defaults write org.xquartz.X11 enable_iglx -bool true
    On XQuartz 2.7 or older the setting is org.macosforge.xquartz.X11 instead.

More help with OpenGL over X11 forwarding: this Stack Exchange thread, the Dartmouth help page and the Columbia help page.

Windows

Pick one of these:

  • MobaXterm: an SSH client with an X server built in, so windows from the server open as soon as you connect. For OpenGL, set its X11 rendering setting to software if the hardware option shows nothing.
  • PuTTY for SSH plus a separate X server: Xming or VcXsrv. Start the X server first, then turn on Enable X11 forwarding in PuTTY under Connection, SSH, X11. This PuTTY and Xming guide walks through it.
  • WSL 2 on Windows 11 (or Windows 10 build 19044 and later) runs Linux window programs directly, with no extra X server. Follow the Linux steps inside it.

Linux

Open a terminal and install the compiler and the X11 and OpenGL development files (Ubuntu and Debian package names):

sudo apt-get update
sudo apt-get install build-essential libx11-dev libxext-dev  # X11 programs (CMPS 3600)
sudo apt-get install libglu1-mesa-dev freeglut3-dev mesa-common-dev  # OpenGL (CMPS 3350)
sudo apt-get install x11-apps mesa-utils  # xeyes and glxgears for the tests below

Programs with sound also need OpenAL and ALUT:

sudo apt-get install libopenal1 libopenal-dev libalut0 libalut-dev

Source for the OpenGL and OpenAL packages: this Stack Overflow post.

Check that it works

Run these on the machine where the labs run (your Linux computer, or the server you connected to).

TestWhat you should seeWhat it proves
xeyesA pair of eyes that follow your mouseX11 windows work
glxgearsThree gears spinningX11 and OpenGL work

Close each test window, or press Ctrl-C in the terminal, before starting a lab.

If nothing appears

  • "cannot open display" or "could not open display": the X server is not running, or SSH was started without -Y (or PuTTY's X11 forwarding is off). echo $DISPLAY should print something such as localhost:10.0.
  • xeyes works but glxgears does not: X11 is fine and OpenGL is the problem. On a Mac, check the XQuartz setting above; with MobaXterm, try software rendering.
  • A build fails with X11/Xlib.h: No such file or GL/gl.h: No such file: the development packages from the Linux section are missing on the machine that builds the program.
